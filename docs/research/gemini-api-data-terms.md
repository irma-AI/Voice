# Gemini API and Vertex AI data terms

Retrieved 2026-10-18. Question: what Google's current terms say about data sent to the Gemini API (AI Studio developer API, `generativelanguage.googleapis.com`, API key) and to Vertex AI's Gemini models, as they matter to a GDPR processor in Sweden sending caller audio and a Business's facts to the Gemini Live API (`gemini-3.8-live`, Pipecat 1.12.0 `GeminiLiveLLMService`).

All Google pages below were read through a page-to-markdown summarizer plus `curl` text extraction, not the rendered page. Quotes are short; re-read the page before any quote goes into a legal text. Google renamed Vertex AI to "Gemini Enterprise Agent Platform" in its docs; `cloud.google.com/vertex-ai/...` URLs now 301 to `docs.cloud.google.com/...`. Both forms are given where that happened.

## 1. Gemini API Additional Terms of Service: Unpaid vs Paid

Source: https://ai.google.dev/gemini-api/terms ("Effective March 23, 2026", page "Last updated 2026-04-28 UTC"; read 2026-10-18).

- What makes a project paid: "Your access to Gemini API is a 'Paid Service' only when accessing the API through a Cloud Project associated with an active billing account." An AI Studio account also counts as paid when it "has access to a Cloud Project with an associated and active Cloud Billing account" (or is a Workspace enterprise account). So: Cloud Billing on the project, not the key, decides.
- Unpaid Services, data use: Google uses content "to provide, improve, and develop Google products and services and machine learning technologies", and "human reviewers may read, annotate, and process your API input and output" (disconnected from the account, key and project first). The terms say: "Do not submit sensitive, confidential, or personal information to the Unpaid Services." No retention period is stated.
- Paid Services, data use: "Google doesn't use your prompts [...] or responses to improve our products." The paid section does not mention human review at all (that language sits only under Unpaid); it does say Google "logs prompts and responses for a limited period of time, solely for detecting and preventing violations" of the Prohibited Use Policy and for legal disclosures. No duration is given in the terms (see § 2).
- EEA, Switzerland, UK: "If you're in the European Economic Area, Switzerland, or the United Kingdom, the terms under [Paid Services: How Google Uses Your Data] apply to all Services, including Google AI Studio and unpaid quota in the Gemini API." So an EEA account gets the paid data terms even on free quota; the pricing page's free-tier "used to improve our products: Yes" column is overridden by this sentence for EEA users (the two pages read differently; the terms govern).
- Processing location: the only sentence is "This data may be stored transiently or cached in any country in which Google or its agents maintain facilities." The terms make no data residency or regional processing commitment, and the Gemini API has no region parameter. The "available regions" page (https://ai.google.dev/gemini-api/docs/available-regions, last updated 2026-04-28) lists Sweden and every EEA state as places the API can be used from and says nothing about where data is processed.

## 2. Abuse monitoring and logging retention (Gemini API)

Source: https://ai.google.dev/gemini-api/docs/abuse-monitoring ("Last updated 2026-06-09 UTC"; read 2026-10-18). `https://ai.google.dev/gemini-api/docs/usage-policies` serves the same page.

- "Google retains the following data for fifty-five (55) days for the purposes of detecting and preventing violations" of the Prohibited Use Policy and for legal disclosures. Retained: the prompts, any context sent with them, and the generated outputs. For a voice call that is the caller audio, the Business's facts in the system instruction, and the model's audio.
- "Data can be accessed for human review only by authorized Google employees", through an internal governance platform.
- "It is not used to train or fine-tune any AI/ML models besides those used specifically for policy enforcement."
- Scope: "These policy guidelines apply to the use of the Gemini API and AI Studio." The page does not split paid from unpaid, and it offers no way to turn the logging off or shorten it. No opt-out, exception form or zero-data-retention option exists for the Gemini API on these pages. Not verified: whether the 55 days is counted from submission or from flagging.

## 3. Which data processing terms apply to the paid Gemini API

- The Gemini API terms (§ 1 source) say prompts and responses for Paid Services are processed "in accordance with the Data Processing Addendum for Products Where Google is a Data Processor", linking https://business.safety.google/processorterms/ ("Version 10", "7 May 2026"; read 2026-10-18). They do not point at the Cloud Data Processing Addendum. Account and usage data stay under the Google Controller-Controller Data Protection Terms.
- That processor DPA covers "the applicable services listed at business.safety.google/services/". That list (https://business.safety.google/services/, "Last update: 27 April 2026") names "Gemini API Paid Services", data type "Personal data processed by Gemini API Paid Services in submitted prompts and responses to those prompts". AI Studio and the free tier are not on the list. So: the paid Gemini API does have a DPA, Google's general processor DPA (the same instrument as for Workspace Individual, RCS Business Messaging and others), not the Google Cloud one.
- Data location in that DPA, § 10.1: "Google may process Partner Personal Data in any country in which Google or its Subprocessors maintain facilities", subject to the transfer terms in Appendix 3 (EU SCC-based transfer solution; EU-US Data Privacy Framework certification for some US subsidiaries). No location selection.
- Subprocessors: the DPA § 11.2 points at https://business.safety.google/subprocessors/ ("Last update: 12 December 2025"). That page lists subprocessors for RCS services only (two HCL entities) and links onward for Workspace Individual and Voice Starter. It does not mention the Gemini API. No subprocessor list for "Gemini API Paid Services" was found on 2026-10-18: not verified whether one exists elsewhere.
- Google Cloud's subprocessor list, https://cloud.google.com/terms/subprocessors ("Last modified August 20, 2026"), covers "the Google Cloud Platform Services"; its rows name "AI Platform/Gemini Enterprise Agent Platform (formerly Vertex AI), Generative AI Services and Agentic AI Services" (data labeling, technical support). The text contains no "Gemini API", "AI Studio" or "Developer API". It covers Vertex, not the AI Studio API.
- The Cloud Data Processing Addendum, https://cloud.google.com/terms/data-processing-addendum ("Last modified June 8, 2026"), applies to the products in its Appendix 4 (Google Cloud Platform, Workspace, Looker, SecOps, Implementation Services, Skills). Gemini API and AI Studio do not appear in it. Its § 10.1: Customer Data "may be processed in any country where Google or its Subprocessors maintain facilities", "Subject to Google's data location commitments under the Service Specific Terms".

## 4. Vertex AI Gemini

Vertex AI is a Google Cloud Platform service, so the Google Cloud Platform Terms of Service and the Cloud Data Processing Addendum (§ 3, last bullet) apply, and its subprocessors are the Google Cloud list. Confirmed on the data governance page: "More details about how Google processes data can also be found in Google's Cloud Data Processing Addendum (CDPA)", and abuse monitoring is scoped to "customers whose use of Google Cloud is governed by the Google Cloud Platform Terms of Service".

Data governance and zero data retention. Source: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/data-governance (page title "Gemini Enterprise Agent Platform and zero data retention", "Last updated 2026-10-15 UTC"; read 2026-10-18).

- "Google won't use your data to train or fine-tune any AI/ML models without your prior permission or instruction." Applies to "all managed models [...] including GA and pre-GA models".
- Caching: "By default, Google's published Gemini models cache Customer Data to reduce latency"; the in-memory cache is deleted "no later than 24 hours after it's written" and "processed in the region that serves the request". Caching is turned off per project with a PATCH to `.../cacheConfig` with `"disableCache": true` (needs `roles/aiplatform.admin`); `retentionType: EPHEMERAL` keeps only the in-memory cache.
- Live API specific: "Session resumption for Gemini Live API is disabled by default"; when enabled it stores "text, video, and audio prompt data and model outputs" for up to 24 hours. "To achieve zero data retention, do not enable this feature." Pipecat 1.12.0 exposes session resumption as a setting; its default was not checked here.
- Request-response logging "is disabled by default." Grounding with Google Search (3 days) and Maps (30 days) store data and cannot be disabled: not relevant unless those tools are switched on.
- Abuse monitoring. Source: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/abuse-monitoring ("Last updated 2026-10-15 UTC"). For standard Google models Google may log prompts when automated classifiers flag them; "This data is stored securely for up to 90 days in the same region or multi-region selected by the customer for their project and adheres to Google Cloud assurances, such as Data Residency"; "Authorized Google employees may assess the flagged prompts"; "This data won't be used to train or fine-tune any AI/ML models." Opt-out: "Customers in scope: Only customers whose use of Google Cloud is governed by the Google Cloud Platform Terms of Service. This means that customers with a Google Cloud Master Agreement are exempt from prompt logging for this abuse monitoring by default." The page has no self-service exception form (the form earlier versions of this page had is gone); for Advanced AI features "It may not be possible to opt-out of prompt-response logging [...] Please contact your account team." So a pay-as-you-go (online terms) project is in scope for abuse logging; a Cloud Master Agreement customer is out by default.

Regions. Source: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/locations ("Last updated 2026-10-15 UTC"; `curl` text checked, not only the summarizer).

- `gemini-3.8-live` appears in the model table of every region group on the page: Global endpoint, United States multi-region, European Union multi-region (`eu`, host `aiplatform.eu.rep.googleapis.com`), United States, Americas, Europe, Asia Pacific, Middle East. The Europe group lists europe-west1 (Belgium), west2 (London), west3 (Frankfurt), west4 (Netherlands), west6 (Zürich), west8 (Milan), west9 (Paris), europe-north1 (Finland), europe-central2 (Warsaw), europe-southwest1 (Madrid). No europe-west12, no Stockholm.
- The page itself warns: "Endpoints don't guarantee data residency or in-region ML processing", "Don't use the global endpoint if you have ML processing requirements", the global endpoint "doesn't support data residency requirements", and multi-region endpoints are meant so that "machine learning processing of Customer Data by the service stays within a specific jurisdictional boundary".
- The Live API overview, https://docs.cloud.google.com/vertex-ai/generative-ai/docs/live-api ("Last updated 2026-10-15 UTC"), lists `gemini-3.8-live` and `gemini-live-2.5-flash-native-audio` as "Generally available" over a "Stateful WebSocket connection (WSS)" but carries no region list of its own, and the locations page does not mention `bidiGenerateContent`. So the EU availability of the Live API rests on the model table alone. Not verified: that a Live session to `europe-west*` or `eu` actually opens (a forum post from 2026 reports "your project does not have access" for `gemini-3.8-live` on Vertex in us-central1 while the 2.5 Live model worked, suggesting an allowlist; one user report, not Google's page).

Data residency. Source: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/data-residency ("Last updated 2026-10-15 UTC"). "Data stored at rest in the customer selected location remains at rest in that location" regardless of endpoint; for ML processing "The geographic location of this processing is determined by your choice of endpoint", a locational endpoint keeps it "within the broader multi-regional or country jurisdiction"; "The European Union multi-region (eu) endpoint strictly covers data residency within EU member states" (UK and Switzerland excluded); global endpoints "don't provide any data residency guarantees". No separate rule for streaming or audio.

## What this means for Voice

- Today's path (AI Studio API, API key) is a Paid Service only if the Cloud project behind the key has an active Cloud Billing account (not seen from the repo: Petter confirms). As a Paid Service: no training on prompts or outputs, and the processor DPA at business.safety.google/processorterms covers "Gemini API Paid Services".
- On that path every call's audio, the Business's facts and the model's replies are kept 55 days for abuse monitoring, readable by authorised Google staff, with no opt-out and no region: "any country in which Google or its agents maintain facilities".
- An EEA account gets the paid data terms even on free quota, but the 55-day log still applies.
- Vertex AI puts the same model under the Google Cloud Platform Terms and the Cloud Data Processing Addendum, with the Google Cloud subprocessor list, a chosen region (the `eu` multi-region and ten European regions list `gemini-3.8-live`) and at-rest residency in that region.
- On Vertex, abuse logging is up to 90 days, in the project's region, only on classifier flags; a Cloud Master Agreement removes it by default, pay-as-you-go online terms do not.
- Vertex caching (24 hours in memory) is on by default and can be switched off per project; Live session resumption is off by default and holds audio for 24 hours when on.
- Pipecat 1.12.0 already ships `GeminiLiveVertexLLMService` (service account or ADC, `project_id`, `location`); the AI Studio class and the Vertex class share everything else.
- Both platforms bill the Live API per token (per turn on Vertex); figures are in `docs/research/gemini-live-pricing.md`.
- Neither platform offers an in-Sweden region; the nearest listed are Finland (europe-north1) and the EU multi-region.
